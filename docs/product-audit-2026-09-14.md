审核日期：2026-09-14。基准：用户提供的农业科普／论坛需求，当前仓库 main（6e77176）。

## 结论

现有网站具备可演示的农业问答 MVP 基础：视觉风格统一，提问支持地区、分类、图片，回答支持引用、赞踩、评论、采纳和商业声明，也有账号与持久化存储。

距离产品目标最大的差距在于：用户描述现场条件的能力有限，专家邀请没有接收端，收藏与关注缺少回访入口，专家身份与活跃积分混淆。建议优先完成“本地问题 → 合适的真人收到邀请 → 回答与追问 → 实践反馈”的完整流程，再投入兑换和商城。

## 优先修改：让核心体验成立

### 1. 建立本地化的提问与找人机制

页面实测：搜索框提示可以输入城镇；已有小麦问题地点是 Horsham，但搜索 Horsham 返回 0 条。代码只匹配问题标题、正文和标签，未匹配 town/state；人物搜索还忽略地区与分类过滤。

修改建议：

- 搜索分为“问题／专家／用户”；专家目录在关键词为空时也可浏览。地区筛选应作用于对应结果，专业筛选使用明确的专业标签。
- 搜索匹配州、城镇和标签；加入最新、最多回答、未回答、专家已回答。保留筛选在 URL 中，便于返回和分享。
- 提问先选 Crops／Livestock，再出现少量相关可选字段：品种或动物种类、生长阶段或日龄、出现时间、影响范围、近期条件、已采取措施。允许“不确定”。
- 地点默认选择用户资料中的地区，未设置时显示“请选择”，避免表单当前默认 ACT 导致误填；公开到城镇／地区即可，无需公开精确农场地址或 IP。
- 邀请专家先按领域与服务地区筛选，显示推荐依据；补站内通知、“待我回答”、已读／已回答状态。

依据：[搜索实现](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:174)、[提问表单](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:139)、[专家列表](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:168)、[邀请 API](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/api/community/route.ts:214)。

### 2. 区分贡献、专业身份与解决结果

代码确认：200 XP 会在个人主页显示 Expert；每发一条回答奖励 10 XP。未经他人认可的 20 条回答即可达到该称号。提问者还可采纳自己的答案并获得奖励。

- XP 对应“新成员／贡献者／资深贡献者”等社区等级；认证专家单独申请与人工审核。
- 农场主、从业者、品牌代表属于角色；认证领域、服务地区、资质依据属于专业信息；三者分开显示。
- 允许分享自己的解决方法，但自问自答的采纳不发额外奖励；兑换前补重复内容、刷赞、关联账户等反作弊与奖励撤销规则。
- 将“提问者已采纳”“社区高票”“专家已回答”“实践后有效”分开。当前选中答案便显示 Resolved in the field，尚无实践结果支撑，应改为准确的采纳描述。
- 增加提问者后续反馈：是否改善、尝试了什么、现场条件有什么变化。农业知识的可复用性取决于这些信息。

依据：[等级计算](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:20)、[回答奖励](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/api/community/route.ts:146)、[采纳奖励](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/api/community/route.ts:194)。

### 3. 首页提高浏览效率，保留现有视觉风格

桌面与手机实测：首页首屏都被宣传文案和牧场大图占据，具体问题位于下方。现有深绿、奶油白、陶土色与农业主题协调，可继续使用。

- 缩小宣传区，首屏提供搜索、地区选择和至少一条真实问题；登录后优先展示“本地区／关注／待回答”的信息流。
- 问题卡片使用“标题＋地区／对象＋简短背景＋答案摘要＋回答状态”。限制普通配图高度，现场诊断照片在详情中展开。
- 详情页采用“标题与关键条件 → 采纳／高票摘要 → 问题完整背景 → 全部回答”。摘要保留跳转原回答入口和商业标签，避免截断导致建议失去适用条件。
- 可以展示一个采纳答案和一个高票参考答案，不必强迫作者选两个 best answer；无答案时明确显示等待回答。
- 标题长度建议作为写作提示，避免机械限制为 10–20 个字或单词而损失症状和场景信息。

依据：[首页](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:108)、[问题页内容顺序](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:171)。

### 4. 手机端补齐持续可达的导航

390px 宽度实测：顶部只剩 Logo 与登录入口。代码在小屏隐藏主导航、搜索图标和顶部提问按钮，未提供替代菜单；手机信息流也隐藏 selected-answer 摘要。

建议提供底部导航或紧凑菜单，至少包含“问题／搜索或专家／提问／我的”。保留一至两行精选摘要；筛选可折叠，避免手机搜索页整个首屏被介绍和筛选占满。编辑和举报使用站内表单，替代浏览器 prompt；主要按钮和次要文字保持足够的触控面积和可读性。

依据：[响应式规则](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/globals.css:134)。

### 5. 收藏、关注、邀请都需要后续入口

- 实现个人主页 Follow；增加“我的问题／回答／收藏／关注／待我回答”。
- 收藏解决“以后查找”，关注解决“收到更新”；在产品上区分这两个用途。
- 第一阶段通知涵盖新回答、评论回复、专家邀请和答案被采纳即可，暂时不需要私信。
- 资料支持昵称、头像、简介、从业年限、擅长领域、地区的编辑。新注册用户当前写入通用简介与领域后无法修改。
- 未登录者点击需要账号的操作时提供明确登录入口，并保留提问草稿和返回地址。
- 首页 Join weekly email 是空按钮；实现订阅流程之前应移除该入口。

## 商业合作与兑换建议

产品推荐优先回答“为什么适用于这个问题、在哪些条件下用过、有哪些限制”，可附产品卡片。将关系清楚区分为普通自购、免费试用、付费合作、品牌雇员；所有展示位置继承标签，专家认证不等于为产品背书。

XP 用于贡献声望；Token 用于兑换，应独立记账。兑换需要到账／撤销流水、库存、兑换订单、履约状态、重复提交保护和历史记录。若首版需要验证奖励动机，可从少量合作商优惠券试点，明确发放与核销规则；实物与付费咨询后续再做。

不建议在专家响应和贡献质量尚未验证前，让“发回答就赚可兑商品的 Token”成为主要激励，否则容易吸引低质量灌水。

## 开发时顺带处理的可靠性缺口

- 提问／回答上传失败返回 null 后仍继续发布，可能丢失关键现场照片。应停止发布、保留文本并允许重试。[提问提交](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:130)、[回答提交](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:169)。
- 回答和评论在 await 之后使用 event.currentTarget.reset()，存在事件目标已清空而抛错的风险，尚未在登录态复现。应提交前保存表单引用，并验证一次提交只生成一条记录。[评论提交](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:150)。
- 页面等待全量社区数据；请求失败没有明确错误、重试入口。每次操作还重新取全量数据，数据增长后应改成分页问题列表、单题详情、本人状态等接口。[数据加载](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/community.tsx:222)。
- 主要正文依赖客户端获取，问题页还共用站点标题。建议服务端输出公开题目、正文与答案摘要，添加逐题标题和分享描述，改善分享与搜索发现的稳定性。[布局元信息](/Users/chongmiw/Documents/Crimson/project/groundedAus/app/layout.tsx:8)。
- 当前测试主要检查源码字符串和文件存在，不能证明注册、发帖、收藏、邀请、举报等真实交互可靠。[现有测试](/Users/chongmiw/Documents/Crimson/project/groundedAus/tests/rendered-html.test.mjs:7)。

## 建议排期与验收

| 顺序 | 交付范围 | 通过标准 |
|---|---|---|
| 第一批：可信试用底座 | 数据边界、上传限制、真实统计、贡献与认证分离、最小审核端 | 游客不能读取他人私人行为；不接受主动内容图片；无虚增计数；发帖不能自动获得认证身份；举报可处理 |
| 第二批：核心使用路径 | 手机导航、紧凑信息流、农业场景提问、城镇／专家搜索、邀请通知、资料与收藏列表 | 手机可直接搜索／提问；Horsham 能搜到既有问题；按地区筛选专家准确；邀请接收者看得到；收藏后能找回 |
| 第三批：经验沉淀 | 实践反馈、内容修订、完整产品披露、领域／地区贡献榜 | 采纳与有效反馈分开；编辑记录可见；商业标签不随摘录丢失 |
| 第四批：验证后扩展 | Token／优惠券试点，再逐步增加实物兑换、私信、付费咨询、AI 与商城 | 奖励可追溯、可撤销；兑换不重复扣款、不超卖；沿用已验证的专家和审核机制 |

验收时使用提问者、专家、普通成员三个独立测试账号，至少跑通：注册完善资料 → 提问并上传图片 → 搜索找到问题 → 邀请专家并收到通知 → 回答与追问 → 采纳及实践反馈 → 收藏后找回 → 举报后由审核员处理。另测游客提示、手机导航、上传失败与重复提交。

运营观察应优先看首次有效回答耗时、未回答问题比例、本地／相关领域专家响应率、提问者实践反馈率和回访率，再观察 Token 对质量的影响。现阶段不建议用硬编码的用户量或答案量作为增长证明。
